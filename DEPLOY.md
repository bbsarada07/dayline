# Deploying Dayline

Dayline is one Docker container: FastAPI serves the API, the realtime WebSocket and the built frontend on one URL. The recommended free host is **Render**. The same `Dockerfile` also runs on Hugging Face Spaces (paid plan needed for Docker Spaces) and anywhere else that runs a container.

## Why not Vercel

Vercel runs short-lived serverless functions, and Dayline needs one long-running process. On Vercel's free plan:

- The SQLite database and the live event hub would split across function instances, so an order placed on one instance might never reach the kitchen screen served by another.
- WebSocket connections close after 5 minutes.
- Scheduled jobs run at most once a day. Dayline's housekeeping (no-shows, print expiry) runs every minute.
- Request bodies are capped at 4.5 MB. Dayline accepts PDFs up to 20 MB.

## Render (recommended, free)

### What you get on the free plan

| | |
|---|---|
| Price | Free: 750 instance hours a month, enough for one service running all month |
| Size | 0.1 CPU, 512 MB RAM |
| Sleep | Stops after 15 minutes with no traffic; the next visit wakes it in about a minute. A free uptime monitor (step 5) keeps it awake. |
| Disk | Temporary. The database and uploaded PDFs reset on every deploy, restart or sleep. Dayline re-seeds an empty database on boot, and the demo clock starts again at Monday 12:20. |
| Realtime | WebSockets supported |
| Deploys | Every push to `main` on GitHub redeploys automatically |

### Steps

1. **Open the deploy link:**
   https://render.com/deploy?repo=https://github.com/bbsarada07/dayline
2. **Sign in to Render with GitHub** when asked. This is the authorisation step: Render gets read access to the repo so it can build it. No card is needed for the free plan.
3. Render reads `render.yaml` and shows one service, **dayline** (Docker, free plan, Singapore). Press **Deploy Blueprint**.
4. Wait for the first build (about 5–10 minutes). Render shows the URL, for example `https://dayline-xxxx.onrender.com`. Open:
   - `https://<your-url>/api/health`: should say `"status": "ok"` with 6 students;
   - `https://<your-url>/`: the login screen with "Try the demo".
5. **Keep it awake (recommended before judging):** create a free monitor at https://uptimerobot.com (or https://cron-job.org) that requests `https://<your-url>/api/health` every 5 minutes.
6. **Later phases:** in Render, go to the service, then **Environment**, and add the integration keys as you reach each phase. Saving redeploys.
   - Phase 6: `QDRANT_URL`, `QDRANT_API_KEY`
   - Phase 7: `LYZR_API_KEY` and the five `LYZR_*_AGENT_ID` lines printed by `python -m scripts.setup_lyzr --apply`, then change `AGENT_MODE` to `lyzr`. Optional: `LYZR_DAILY_CALL_LIMIT` (default 100) to cap credit use; `TOOL_KEY` only if an agent hosted elsewhere will call `/api/agent-tools/*`.
   - Phase 8: `OMI_APP_ID`, `OMI_APP_SECRET` (the private Omi app's id and API key; only needed for replies on a real phone; the simulator works without them). Omi calls the deployed URL, so keep the service awake (step 5) while testing with a real Omi.

`SECRET_KEY` is generated by Render. `PUBLIC_BASE_URL` is filled in automatically from Render's own URL, so you don't need to set it.

### Using the demo

- The banner shows **Demo time** (starts Monday 12:20 and runs forward) and **Reset demo**. Reset demo re-seeds all data for everyone and puts the clock back. It can be used once every 10 seconds.
- Demo accounts are listed on the login screen; every one uses PIN `1234`.
- Staff desks show **Simulate scan**, so collection can be tried without a barcode scanner.

## Hugging Face Spaces (alternative, paid)

Docker Spaces need a Hugging Face PRO account. Steps:

1. Create a Space: SDK **Docker**, hardware **CPU basic**.
2. Push this repo to the Space, with this block added at the top of the Space's `README.md`:

   ```yaml
   ---
   title: Dayline
   sdk: docker
   app_port: 7860
   ---
   ```
3. Add the integration keys under **Settings → Variables and secrets**. `SPACE_SIGNING_SECRET` and `SPACE_HOST` are provided by Hugging Face and used automatically.

## Any other container host

```sh
docker build -t dayline .
docker run -p 7860:7860 -e SECRET_KEY=<random> dayline
```

Then open http://localhost:7860. Set `PORT` if the host expects another port, and `PUBLIC_BASE_URL` to the public HTTPS URL.
